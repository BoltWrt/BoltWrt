# BoltWrt 4.0.0 P0 验收清单

本清单按用户原 P0-1～P0-6 编号记录完成条件和证据。截至 2026-10-23 编写时，**六项 P0 均未整体关闭**。RAX 已完成一次完整 world，正常 runner 的 build／images／最终退出码均为 0，真实 manifest 和镜像已导出本地；随后发现原镜像检查漏检 recovery 容量，新预算门禁对该批产物实际退出 1，recovery 仍不合格。x86 已完成部分必要后端，完整 world 尚未启动。用户尚未通知运行环境可用，未开展设备启动、真实升级或网络验收。

这是一份状态快照。`e1af37c` 下两平台 prepare＋defconfig 和顶层 `make download` 已通过，但该下载目标未覆盖随后编译补取的 host 源码。两平台 host 工具、交叉工具链及 Go 1.26.9 host 编译均退出 0。CMCC 首轮因 Go 1.4 bootstrap 不支持 linux/arm64 宿主而退出 2；后续两卷分别使用容器固定 Go 1.26.8，从锁定源码构建并安装 Go 1.26.9。两平台均已生成各自架构的 Linux 6.12.112 内核 ELF。RAX 的 Python 3.13.15、Rust/Cargo 1.96.0 已源码安装，sslocal 实际 APK 静态检查通过，完整 world 已正常结束；这只闭合该实际 RAX 选中构建图所需输入，不代表全部架构或全部 Cargo.lock 条目。x86 工作卷完整恢复后，SmartDNS、OpenVPN、dnsmasq-full、firewall4 及 Nginx 组独立 compile 均退出 0；Nginx 八包静态检查及本平台 native Python 3.13.15 的 SSL 导入／LZMA 往返检查通过，完整 world 仍未启动。内核 ELF、单包 APK 和固件文件生成都不能替代启动验收。

本轮两平台构建所用源码均为 `883b0d4e`，已包含独立审查及 native UCI 7 项通过的 Aliyun 修复 `30b596e6`／`b63fe068`。同步仅在各自无 make 时精确替换已审查的 8 项差异并保留原内容；随后两平台重复准备的配置及完整源记录保持相同。后续结果须补入对应行，不能从“代码已修复”“配置选择保留”推定编译或运行通过。最终依赖以 [config/source-lock.json](../config/source-lock.json) 为权威；同时保存实际主仓 commit、锁／配置 SHA256 和有效命令行覆盖，避免混用不同输入。
