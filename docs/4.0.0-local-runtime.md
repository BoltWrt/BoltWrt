BIOS IMG 客体实际 APK 3.0.5 数据库为 333 包。使用匹配构建的本地正常签名索引及原公钥，完成查询、Zabbix 7.0.31-r1 卸载／安装及程序版本检查；真正执行 `apk upgrade boltwrt-defaults`，版本由 2 升至 3。测试结束时包身份集合和 world 约束恢复；空 keys 更新索引返回 5、数据库不变。这里的版本升级不是 fetch 或 reinstall 的改称，也未无差别升级整机。

Chrome 中已观察 Dashboard、软件包、SmartDNS、DDNS、PassWall2／组件、SQM、UPnP、OpenVPN、ocserv、frpc 页面，并在接口对话框实际选择 WireGuard VPN 协议。取消按钮当时被空名称校验拦住，随后重载丢弃对话框；没有新增／保存 WireGuard 接口，不声称隧道配置或握手成功。客体复核只有 loopback／lan，网络无 pending。SmartDNS 页面保存受控 server_name 后由真实 UCI 复核，保持 enabled=0／无进程，随后恢复为 name 不存在、enabled=0、无 pending；没有启用对端服务。

软件包页面的正常查询、更新列表、按包名安装／移除和失败可见性已有实际操作。Chrome“更新”页面还实际显示 defaults 2→3，并执行 `apk upgrade boltwrt-defaults`，出现真实 Upgrading (2 -> 3)／333 packages 成功结果；客体最终 installed／world 与基准逐字节一致，LAN /18 无 pending、旧 99 hook 不存在。**旧 helper 的手动 URL 安装失败是真实缺陷**：APK 3.0.5 将 HTTP URL 当成包名，连有效本地 APK URL 也失败。修复提交 `faa71e28` 只对 APK add 的单个 HTTP(S) URL 先下载到私有随机文件，再走正常 APK 信任／依赖检查；显式增加 uclient-fetch 依赖，修改后的包身份为 `26.288.56989~75a306d-r1`，保留 opkg 分支和其他动作，私有输出／清理与稳定 flock inode 均已审查。
