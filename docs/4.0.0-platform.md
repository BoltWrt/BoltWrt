# BoltWrt 4.0.0 平台与运行默认迁移

基于 OpenWrt v25.12.6（64900e756efa667774214f9c6b17c113222e01f7），从旧仓实际提交 12b8f85b 的配置和 Git 历史提取用户功能，不复制旧版生成配置、内核配置或整块驱动代码。

配置加载顺序为 `config/version.txt`、`config/common.txt`、`config/targets/<目标>.txt`。版本字段独立维护。common 仅声明发行版功能和必要后端，由新上游及锁定 feeds 解析依赖；平台片段只声明目标、镜像及平台专属功能。原有启用的依赖库、旧内核符号和工具链参数由新版本重新计算，不能把旧 `.config` 当成新版本功能清单。

## 平台与镜像

| 目标 | 保留的镜像与功能 |
| --- | --- |
| x86-64 | BIOS、UEFI；SquashFS `combined.img.gz` / `combined-efi.img.gz` 与对应 VMDK；kernel 32 MiB、rootfs 384 MiB；GRUB 标题 BoltWrt；Zabbix 与 Cloudflare/GoDaddy/HuaweiCloud DDNS |
| cmcc-rax3000m | 上游 RAX3000M/Me 共用 profile；NAND/eMMC overlays；DDR3-1866、DDR4 各自的 preloader/FIP；rootfs 分区配置 128 MiB；USB 存储及 Samba |

保留新上游 DTS 的 MT7531/AN8855 支持、MT7981B 引用、总线 cells 和 pinctrl 修正。保留上游网络端口及无线 MAC 校准逻辑、WiFi ucode，不恢复旧树为精简平台而删除的其他设备代码。以上是源码支持范围，尚不是各硬件变体的实机验收结论；bootloader 产物必须与实际存储和 DDR 类型匹配。

### NAND 容量边界

上游 NAND overlay 的 `ubi` 区域为 `0x7200000` 字节，即 114 MiB。128 MiB rootfs 配置用于 eMMC production 布局，不代表 NAND 拥有 128 MiB 可写空间。

上游 `package/utils/fitblk/files/fit.sh` 的 `fit_do_upgrade()` 对 UBI 选择 `nand_do_upgrade()`；`package/base-files/files/lib/upgrade/nand.sh` 的 `nand_upgrade_fit()` 使用完整 FIT 文件长度创建 `fit` volume，并以相同长度调用 `ubiupdatevol`。因此最终带 metadata 的 `*-squashfs-sysupgrade.itb` 文件字节数可作为保守的包体准入检查。发布检查要求该文件严格小于 104 MiB，给 114 MiB 原始 UBI 区域保留至少 10 MiB 预算。

104 MiB 是发行版准入预算，不是芯片物理容量公式，也不能保证任意坏块数量下都可刷入。UBI 头、管理及保留块、环境卷、rootfs_data 和坏块都消耗空间。实际 NAND 余量必须在对应设备检查；若完整功能镜像超限，构建应失败，再评估组件体积，不能把“产物已生成”报告为 NAND 已适配。上游镜像定义和 eMMC GPT 不因该预算而修改。

## 新装默认与升级保留

`boltwrt-defaults` 包通过 `etc/board.d/99-boltwrt` 提供 board.json 默认值：LAN `10.126.0.1/18`、hostname `BoltWrt`，以及 `ntp.aliyun.com`、`time.nist.gov`、`ntp.ubuntu.com`、`time.windows.com`。新版本会把 LAN 地址写为 UCI CIDR 列表。

上游 preinit 先恢复 sysupgrade 配置，再执行 config_generate。config_generate 仅为缺失的 network/system 文件生成内容，因而用户已有 LAN、hostname、NTP 均保留；即使用户主动选择上游的 `192.168.1.1` 也不推断为需要覆盖的默认值。重复生成不累加 NTP 条目。

Web 使用官方 nginx → uwsgi → LuCI 栈及 nginx 原生 ubus 模块。仅选择 luci-nginx 集合，不再叠加会引入 uhttpd 的 luci/luci-ssl 集合。Argon 默认、nginx 自签证书主体 CN/Beijing/BoltWrt 与 3650 天由精确幂等的 feed 准备脚本落实；不修改已保存的用户主题、现有证书或用户 Web 配置。uhttpd 的上游文件保持原样。来源检查和配置生成测试不等同于设备上的端口或 TLS 验收。

## Aliyun DDNS 升级

旧 `ddns-scripts_aliyun` 替换为官方 `ddns-scripts-aliyun`，`service_name` 仍为 `aliyun.com`。官方 provider 要求 `RR@DOMAIN`：

| 原配置 | 迁移结果 |
| --- | --- |
| `home.example.com` | `home@example.com` |
| `@.example.com` | `@example.com` |
| `home@example.com` / `@example.com` | 保持原样 |
| 其他 provider | 保持原样 |

uci-defaults 迁移严格模拟旧脚本“第一个点转 @”的解释，不推断公共后缀。username/password、启用状态及其他选项均保留。先检查全部目标 section，再写入；发现不支持的旧输入时返回非零并保留迁移脚本待重试，日志仅报告通用原因，不打印域名、凭证或 UCI 内容。修正后再次执行不会重复转换。

## 最小验证与证据边界

使用一次性 Ubuntu 容器，从基线 Makefile 的固定 SHA 构建真实 UCI 与 libubox/jshn。测试入口为 `package/boltwrt-defaults/tests/test_defaults.py`，要求 `/work` 指向只读项目源码，并在容器 `/lib` 放置对应上游 functions.sh、uci-defaults.sh、ipv4.sh、uci.sh。测试会写容器 `/etc/config`，禁止直接在主机或路由器运行。

覆盖新装 CIDR/hostname/NTP、重复执行、保留升级配置、Aliyun 两种旧格式/匿名 section/新格式/其他 provider/凭证保留，以及无效旧输入不部分迁移。配置解析、源代码边界、最终固件编译和实机运行分别记录；用户未提供运行测试环境前不开展实机验收。

复现时先把以下官方源码归档下载到项目内的忽略目录 `logs/platform-check/`（不安装主机软件）：

- libubox `7dd127841e82eb1cfb61185da37dde7b9bd9ba6d`：`https://codeload.github.com/openwrt/libubox/tar.gz/7dd127841e82eb1cfb61185da37dde7b9bd9ba6d`，命名 `libubox.tar.gz`。
- UCI `66127cd76c5d0bd46d5a90302cc6110f53a4e2f8`：`https://codeload.github.com/openwrt/uci/tar.gz/66127cd76c5d0bd46d5a90302cc6110f53a4e2f8`，命名 `uci.tar.gz`。

```sh
docker run --rm --init --user root \
  -v "$PWD:/work:ro" -v "$PWD/logs/platform-check:/sources:ro" \
  boltwrt-build:4.0.0 bash /work/package/boltwrt-defaults/tests/run-native.sh
```

runner 核对归档顶层目录与当前基线 SHA，在容器使用 TUNA 源补充 libjson-c-dev、编译原生工具，并运行 5 项测试。shell 部分使用容器 Bash 执行上游函数及发行版脚本；这是实际 UCI/JSHN 配置语义测试，尚未证明 BusyBox ash、设备启动顺序、无线、TLS 或第三方 DDNS 网络调用。测试仅使用假凭证，并禁止在非 Docker 环境执行。
