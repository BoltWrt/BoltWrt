# 3.1.2 → 4.0.0 升级验证边界

本文件约束本次 P0-6 验证，不构成已经完成兼容验收或允许生产刷写的结论。运行测试环境由用户准备，通知可用后才开展启动、升级及网络测试。

本次旧版本源码核对使用远端 `v3.1.2`：annotated tag object 为 `62c5ad334bde424099820ae8d00df18467dc6fba`，peeled commit 为 `fc2a47325944623d9fd773b313d56fca12752acb`。不能把 tag object 当成源码 commit。

## 已核对的源码行为

- 3.1.2 的普通 sysupgrade 备份保存配置；不会恢复整个旧系统。旧版 `-o` 分支也排除 `/usr/lib/opkg/*`。新版本还排除 APK/opkg 状态，但新版本规则不能证明旧系统自定义备份安全。
- 恢复先于新配置生成；已有 `/etc/config/network`、`system` 不会被新装默认重写。新装才采用 LAN `10.126.0.1/18`、BoltWrt hostname 和预设 NTP。
- 旧 `/etc/opkg.conf`、`/etc/opkg/customfeeds.conf`、`/etc/opkg/keys/` 不等于新 APK 的 `/etc/apk/repositories.d/`、`/etc/apk/keys/`；不自动转换旧 URL 或密钥。
- 新 APK 源固定为 OpenWrt 25.12.6；未部署 BoltWrt APK 仓库，`CONFIG_FEED_BoltWrt=m` 仅生成注释项。自定义包在线安装、更新和与自编内核匹配的模块分发尚无自有服务，不能据上游源推定可用。
- 已核对 nginx 配置目录、OpenVPN 目录、ocserv 证书/密钥/用户配置的现有包声明或 keep.d 保护。无需重复实现整目录复制。
- UCI 里保存文件路径不会自动保存目标文件。位于既有备份范围之外的证书、密钥或自定义脚本，必须在旧系统 `/etc/sysupgrade.conf` 精确登记。用户若显式登记旧包数据库、包二进制或整个 overlay，须先审阅并移除不适合跨代恢复的条目。
- 官方 Aliyun DDNS 替换旧包时，`95-boltwrt-aliyun` 仅迁移 `aliyun.com` 的旧 domain 格式；凭据及其他 provider 不改。异常返回非零并保留迁移入口，不打印配置或凭证。
- 本基线的 `kmod-sched-cake` 所带 `sch_cake.ko` 同时提供 `cake` 和 `cake_mq`，没有可用于判断启用状态的独立 `kmod-sched-cake-mq` 包。固定 SQM 1.7.2 默认 `use_mq=0`；升级保留用户 `use_mq=1` 选择，满足所选脚本支持、设备多 TX 队列及 qdisc 可用条件时可启用 `cake_mq`，迁移不能为迎合默认值而覆盖用户选择。运行验收需同时记录 `uci show sqm` 的 `use_mq`、实际出口和 IFB 的 `tc -s qdisc show`；仅包清单不能证明未启用 `cake_mq`。

依据：历史 `v3.1.2:package/base-files/files/sbin/sysupgrade`、新基线同路径、`package/base-files/files/lib/preinit/80_mount_root`、`config_generate`、`include/feeds.mk`，以及固定 packages feed 的 nginx/OpenVPN/ocserv 包定义。

## 镜像与引导的源码边界

3.1.2 的 RAX DTS 与 overlays 已使用 `mt7981b-cmcc-rax3000m*` 名称，旧 FIP 环境中的 `config-1#...-emmc/nand` 与新 FIT configuration 生成规则相符；未发现需要靠重新刷 FIP 解决的名称断裂。旧 U-Boot 手动 TFTP 默认仍使用 OpenWrt 文件名，BoltWrt 产物和 DDR 后缀需按人工恢复环境正确命名，不能因此把不同 DDR/介质的 bootloader 混刷。

x86 同样保持 SquashFS、BIOS/EFI 和 32/384 MiB 布局，平台升级、移动备份及 GRUB 脚本与旧 tag 一致；分区映射变化仍可能触发整盘写入。新内核的磁盘识别使用 DISKSEQ/PARTN，设备实测尚未执行。上述源码核对不证明 BIOS/EFI 切换、自改分区、扩容、额外数据或特定虚拟磁盘总线已兼容。
