# Guest fixtures for real 3.1.2 → 4.0.0 upgrades

These scripts are test inputs for disposable, real x86 full-disk guests. They never flash, reboot, reload the network or restart services. Root reviews/transfers them and controls QEMU, image identity, actual `sysupgrade` and serial evidence. Running either script in a container/chroot does not prove an upgrade.

Create two independent cases from a clean, cold-stopped 3.1.2 full-disk baseline. In each guest run `sh prepare-312-fixture.sh enabled` or `disabled`. The strict old-version/precondition checks reject an existing fixture, pending UCI changes, custom backup entries or a modified HAProxy default. A failure leaves visible partial state for inspection; use a clean case rather than rerunning over it.

Preparation keeps the management address 10.126.0.1 and changes its mask to /24; sets identifiable hostname/NTP, LuCI's Argon theme (`luci.main.mediaurlbase=/luci-static/argon`) and English language (`luci.main.lang=en`), disabled DDNS/SQM sections without credentials, and SQM use_mq=1; generates a seven-day self-signed certificate/private key and safe unexecuted probe script; points the actual Nginx `_lan` server at that certificate; replaces HAProxy's independent example configuration with a loopback-only listener and sets the selected enable intent without starting it. LuCI is included in the clean-UCI preflight and precise package commits; post-upgrade verification checks both retained LuCI values exactly. It registers exact fixture paths and HAProxy config in sysupgrade.conf. The private SHA manifest includes the temporary test key digest but is never printed. It creates an unregistered file under /usr/local as a negative control.

For cases already prepared before these two LuCI values were added, root may record a supplementary clean-LuCI check, set the two exact values above and `uci commit luci`, then create and retain a **new** standard preflight backup and marker. Do not rerun preparation over an existing fixture or reuse the earlier archive as proof of the supplemented state.

Preparation runs standard `sysupgrade -l` and `sysupgrade -b` into the printed private /tmp preflight directory and inspects the actual archive. Save that archive, its member list and service marker privately off-guest before proceeding. In 3.1.2, the automatically generated `etc/uci-defaults/10_disable_services` always exists, including in the enabled case; it must contain HAProxy's disable command only for the disabled case. Never remove or execute this marker by hand. Preparation's preflight archive is evidence, not the input for a manual restore into 4.0.0.

Root transfers the matching real 4.0.0 full-disk image, verifies its SHA256, records successful `sysupgrade -T IMAGE`, then executes **standard `sysupgrade IMAGE` inside 3.1.2**, recording its continuous serial output and automatic reboot. Do not use -F, -n, -o, -c, -f or an offline backup-copy substitute. This only covers the actual boot/disk combination and controlled inputs used.

After 4.0.0 boots, transfer/run `sh verify-upgrade-fixture.sh enabled` or `disabled`. It checks strict version, retained values/files/digests/permissions, absent negative control, HAProxy enable intent and syntax, cleared 09/10 hooks plus 09 presence in /rom, APK's actual installed database/query, and absence of old opkg database/metadata/executable. Old /etc/opkg configuration or keys may remain; those are not a converted APK repository. The verifier uses `nginx -T -c /etc/nginx/uci.conf`, checks the actual master process command and generated certificate references, and privately retains output. It does not repair or regenerate configuration before checking.

**Separate HTTPS handshake evidence is required.** Local configuration parsing, matching on-disk certificate and a running master cannot prove the certificate served by the existing worker/listener. Through the case's loopback-only HTTPS management forward, root must record a real TLS handshake/HTTP response and compare the served certificate's DER SHA256 with `/root/boltwrt-upgrade-fixture/certificate-der.sha256`, accepting this explicitly temporary self-signed certificate. Do not publish private keys, full Nginx configuration or temporary passwords. The verifier intentionally prints `HTTPS_SERVED_CERTIFICATE_HANDSHAKE=PENDING_EXTERNAL_ROOT_CHECK`; exit 0 means local checks only. Repeat local checks and served-certificate comparison after a guest-initiated reboot.

Also retain the old/new firmware hashes, old opkg baseline, preflight archive, actual image-test/sysupgrade logs, new PID1/board/mount/overlay evidence and observed post-reboot service state. Script success cannot replace that evidence. WAN/service peers/real traffic/wireless tests remain outside this reduced test scope.
